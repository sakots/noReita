# Proposal

## Why

現行の FIT は、ページ構造を固定値で推測して NEO の枠を広げ、同時に倍率を 1 倍へ戻すため、作業領域の配置と描画アプリの表示操作が混在している。NEO v1.8.8 では標準のリサイズ処理が利用できるため、内部処理を複製せず、外部パレットを含む作業領域の専用表示として FIT を組み直す。

## What Changes

- **BREAKING**: FIT をページ内の枠拡大から、NEO と noReita の外部パレットでブラウザーの表示領域を占有する専用表示へ変更する。ブラウザーの Fullscreen API は使用しない。
- **BREAKING**: FIT 開始・専用表示中のリサイズでは利用者が選んだ倍率を保持し、利用者の通常の解除操作でのみ倍率を 1 倍へ戻す。Float への切り替えには倍率リセットを追加しない。
- 専用表示の配置と寸法は CSS、モードと復帰処理は FIT 制御、描画表示と操作部品の更新は NEO 標準の `Neo.resizeCanvas()` に分担する。
- 外部パレット先頭の既存 `FIT!` fieldsetで、通常表示の開始ボタンと専用表示中の「通常表示に戻る」ボタンを同じ位置に切り替える。専用の上部ツールバーと重複する解除操作は設けない。FIT中は同fieldsetをパレット上端へ固定し、長いパレットをスクロールしても解除へ到達できるようにする。
- 背後のページのスクロール・キーボード操作を抑止し、利用者の解除時に開始前のページ位置とフォーカスを復元する。
- 非同期初期化前は専用表示に入らず、利用可能になった後は再読み込みなしで開始できるようにする。
- NEO の Float 開始時は専用表示を解除して Float を優先し、Float 終了後に専用表示を自動再開しない。Float のボタン・確認・処理は変更しない。
- eda と monoreita の両テーマで、専用表示、画面サイズ変更、復帰、Float との切り替え、描画データ保持を実 NEO で検証する。

対象は標準リサイズ処理を公開する NEO とし、実資産の確認基準は v1.8.8 とする。旧 v1.8.7 向けの内部処理の代替実装・互換分岐、NEO 本体・ローダー・配信設定の変更、他のお絵かきアプリ、投稿保存経路、無関係なテーマ共通化は対象外とする。

## Capabilities

### New Capabilities

- `neo-applet-fit`: NEO と外部パレットを専用の作業領域へ切り替え、開始・リサイズ時の倍率と描画データを保持する。通常の解除操作では倍率を 1 倍へ戻して通常表示へ復帰する。既存 FIT の再設計を初めて仕様に登録する。

### Modified Capabilities

なし。既存の OpenSpec 仕様は未登録。

## Impact

- 実装対象: 両テーマの `js/appFit.js`、描画テンプレート、動的パレットの FIT 操作部品、Sass と生成 CSS。旧来の固定寸法計算と操作の呼び出し元も移行し、互換ラッパーは残さない。
- NEO への変更は行わず、連携を配置枠の寸法、標準リサイズ API、通常解除時の `setZoom(1)`、Float の通知に限定する。描画画像・表示用バッファ・コンテキスト・ツール位置を noReita から直接更新しない。
- 検証対象: 両テーマの専用表示と解除、背後の操作抑止、フォーカス・ページ位置の復帰、画面サイズ変更、ズーム・スクロール、Float、非同期初期化、レイヤーと履歴の保持。
- `tests/smoke.php` の FIT テストはソース文字列を検査しており、新しい表示動作を証明できない。実装時に削除し、別の文字列固定テストに置き換えず、実ブラウザーで受け入れ条件を確認する。
- 実装時に `docs/development.md` の検証手順・結果と `README.md`・`changelog.md` の更新履歴を更新する。既存のローダー修正の記録は、専用表示の実装完了を示すものとして扱わない。
- 新しい本番依存・設定・DB 変更・データ移行は不要。今回の計画修正では実装コードを変更せず、新しい専用表示のタスクを完了扱いにしない。
