# Design

## Context

動機と対象範囲は `proposal.md`、受け入れ条件は `specs/neo-applet-fit/spec.md` を参照する。外部公開されていない処理をどう置き換えるか、表示領域と元画像をどう区別するかの技術判断が必要なため、設計を記録する。

### 調査で確認した現状

- 両テーマの `js/appFit.js` は同一内容で、`expand()` と `compress()` が枠を変更し、`resetZoom()` が `setZoom(1)`、`Neo.resizeCanvas()`、引数なしの `updateDestCanvas()` を順に呼ぶ。
- 配信先 `https://oekakibbs.moe/apps/neo/neo.js` のバージョンは 1.8.7。`resizeCanvas` はバンドル内部の関数で、`Neo.resizeCanvas` は `undefined`。
- 実際の配信スクリプトと eda の FIT スクリプト・CSS を使った隔離ブラウザー画面では、1000×1000 の画像、600×600 の初期枠で、FIT 拡大と NEO のズーム後の表示用キャンバスは 820×770 となった。FIT 縮小後は枠が 600×600、倍率が 1 に戻っても表示用キャンバスは 820×770 のまま残り、`Neo.resizeCanvas is not a function` が発生した。
- v1.8.7 の `painter.setZoom(value)` は現在の `neo-container` と元画像から `destWidth`・`destHeight` を計算し、偶数補正する。ただし `destCanvas.width`・`height` と `Neo.canvas` の CSS 寸法は更新しない。
- 内部の `resizeCanvas` は表示用バッファ、描画コンテキスト、キャンバス要素の CSS、ツール配置を更新する。`painter.updateDestCanvas(x, y, width, height, useTemp)` は描画対象の矩形を必要とする。
- `tests/smoke.php` の FIT テストはソース文字列の有無だけを検査している。ブラウザーでの寸法不整合を検出できない。

参照: [配信中の NEO](https://oekakibbs.moe/apps/neo/neo.js)、[上流のコンテナ処理](https://github.com/funige/neo/blob/master/src/container.js)、[上流の倍率処理](https://github.com/funige/neo/blob/master/src/painter.js)。上流 master と配信資産は変化するため、実装時の動作検証には取得した実資産のバージョンとハッシュを記録する。

## Goals / Non-Goals

**Goals:**

- 枠の変更、表示用バッファの変更、視点・スクロール・ツール配置の同期を一連の処理として扱う。
- NEO の倍率計算を再利用し、noReita 側に余白寸法や倍率の計算式を重複させない。
- 元画像用のキャンバスと表示専用のキャンバスを区別し、表示変更で作品データや Undo 履歴を再構築しない。

**Non-Goals:**

- NEO の内部関数をグローバルへ注入すること、旧 API の互換シム、NEO のズームボタンを疑似クリックして内部関数を呼び出すこと。
- 共通 JavaScript 基盤や新しい依存パッケージを導入すること。

## Decisions

### 1. 既存の FIT 管理クラスで表示用バッファを同期する

両テーマの `AppFitManager` 内で、枠の変更後に NEO の表示状態を同期する。テンプレートが呼ぶ `appfit(0)`・`appfit(1)` と既存の枠の拡大寸法計算は維持する。

`painter.setZoom(1)` で得た `destWidth`・`destHeight` を表示用キャンバスの実寸法と `Neo.canvas` の CSS 寸法へ反映する。これにより、画像が領域より小さい場合の制限や偶数補正も NEO の計算結果を使える。描画コンテキストの設定を戻し、1 倍表示としてアンチエイリアスを無効にする。

その後、実際の表示用バッファ寸法に基づいて既存の `setZoomPosition` で視点とスクロールバーを同期し、元画像全体の矩形を指定して再描画する。元画像の `canvasWidth`・`canvasHeight`、各レイヤーのキャンバス寸法・画素・表示状態・履歴は変更しない。

上流の `resizeCanvas` 全体をコピーする案は、余白計算が二重管理になるため採用しない。単に存在判定で呼び出しを省く案も、表示用バッファが古いままになるため採用しない。

### 2. 操作部品も新しい領域に合わせる

NEO の内部のサイズ更新が行っていた `toolsWrapper` の縦方向配置と、小さい高さでの収まりを、新しいコンテナ寸法に合わせて更新する。縮小後にツールが古い位置や変形状態へ取り残されないようにする。ズーム・スクロール操作は NEO の既存ハンドラーをそのまま使う。

### 3. 非同期初期化の前は状態を変えない

FIT 実行のたびに DOM を取り直す既存方針を維持する。必要な DOM と `Neo.painter`・表示用キャンバス・コンテナが準備できていない場合は、枠・ボタン・`isExpanded` を変更する前に処理を終了する。読み込み完了後の操作で再取得するため、新たなポーリングや初期化待ちキューは追加しない。

### 4. 実 NEO を使ったブラウザー検証を主証拠にする

両テーマについて、大きい画像と小さい画像、FIT の反復、拡大後のズームと縮小、縮小後のスクロール・ズーム、描画と Undo/Redo、初期化を遅延させたケースを検証する。表示用キャンバスの CSS 寸法だけでなく、実際のバッファ寸法、画面、コンソール例外も確認する。

既存のソース文字列に依存する FIT テストは削除し、別の文字列へ固定し直さない。現在のリポジトリにブラウザーテストランナーはないため、この変更だけのために恒久的な依存を増やさず、一時的なブラウザー検証で修正前の失敗と修正後の成功を確認し、再現手順を開発資料へ残す。

## Risks / Trade-offs

- NEO が外部公開していない関数に代わり painter と DOM の既存フィールドを利用するため、将来の NEO 内部変更に影響される → 依存を FIT の表示同期処理へ限定し、配信バージョンを明示した実画面検証を残す。
- Canvas の `width`・`height` 代入は表示内容と描画コンテキストの状態をリセットする → 更新は表示専用のバッファだけに限定し、状態復元後に元画像全体を再描画する。元レイヤーはリサイズしない。
- 視点とスクロール位置の計算に古いバッファ寸法を使うと表示がずれる → バッファの実寸法を更新した後に視点を同期し、縮小後のズーム・スクロールを検証する。
- 両テーマに同じ修正を入れる既存構成は重複を残す → 今回は同等の変更と実画面検証に限定し、無関係なテーマ共通化を行わない。

## Migration Plan

両テーマの `js/appFit.js` と更新履歴・検証資料を同時に更新する。PHP、設定、DB スキーマ、投稿画像、NEO の配信設定の変更やデータ移行は不要。問題があれば両テーマの FIT スクリプトを修正前へ揃えて戻す。ただし、このロールバックでは今回の NEO v1.8.7 との不整合も元に戻る。
