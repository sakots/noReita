# Design

## Context

動機・変更範囲は `proposal.md`、利用者から見える受け入れ条件は `specs/neo-applet-fit/spec.md` を参照する。本設計は旧来のページ内拡大ではなく、利用者が選択した「作業領域の専用表示」を扱う。

### 確認済みの現状と設計上の前提

- 両テーマの `AppFitManager` は `scrollWidth - 360` と画面高からの固定減算で枠を広げ、解除時にテンプレート由来の寸法を代入する。`resetZoom()` は `setZoom(1)`、`Neo.resizeCanvas()`、引数なしの `updateDestCanvas()` を呼ぶ。
- 2026/10/18 に確認した NEO v1.8.8 は `Neo.resizeCanvas()` を公開している。標準処理が表示用バッファ、コンテキスト、ツール配置、再描画を更新するため、noReita でこれらを複製する必要はない。
- 実 NEO の Float 操作では、コンテナが `neo-pageView` と `neo-windowView` の間を移動し、`neo:fullscreenchange` が発火した。外部パレットは NEO の外にあり、Float 中は覆われて操作できなかった。Float をそのまま FIT の代わりにはできない。
- 確認した配信資産は `https://oekakibbs.moe/apps/neo/neo.js`、版は 1.8.8、SHA-256 は `f1964a3b64d27fa921012a9bb784ec38c4117efb85449fd86a26e7af17e1c056`。既存 FIT と Float の調査結果であり、新しい専用表示の動作証拠ではない。
- 相対パス対応を含むローダー修正は別途実施済み。本変更ではローダーを変更せず、実装時に利用する資産の版とハッシュを再記録する。

参照: [配信中の NEO](https://oekakibbs.moe/apps/neo/neo.js)、[上流の表示切り替えとリサイズ](https://github.com/funige/neo/blob/master/src/container.js)、[Float の確認処理](https://github.com/funige/neo/blob/master/src/commands.js)。

## Goals / Non-Goals

**Goals:**

- 作業領域の配置、FIT の状態管理、NEO の描画表示更新の責務を分離する。
- 通常表示へ戻す際に寸法を再構築せず、FIT が変更したレイアウト指定と背景操作の抑止を解除する。
- 倍率・作品データを FIT の状態から切り離し、NEO と外部パレットの DOM・フォーム・イベントを維持する。

**Non-Goals:**

- NEO 本体・Float のボタンや確認・描画ハンドラーの変更、内部関数の注入、旧版向け互換シム。
- ブラウザーの Fullscreen API、NEO 全体の CSS 縮尺変更、描画座標の補正。
- テーマ共通基盤、新しい本番依存、投稿保存経路の変更。

## Decisions

### 1. 専用表示は noReita のレイアウトモードにする

`#appstage` を専用表示の単位とし、既存 DOM を移動・再生成せず、FIT 用クラスで表示領域を覆う固定配置へ切り替える。描画枠、外部パレット、常時操作可能な解除操作を CSS Grid で割り当てる。通常表示には FIT 用の指定を適用しない。

NEO が生成する `neo-pageView` の枠だけを FIT 中の配置領域へ合わせる。NEO 内部のキャンバス寸法やツール位置は CSS でも上書きしない。背景のヘッダーを覆う位置と、NEO の確認・メニューを妨げない重なり順を両テーマで検証する。

長いパレットは独立してスクロール可能にする。狭い・低い画面で操作部品が収まらない場合は、配置領域内のスクロールで到達可能にし、はみ出しを単に隠したり NEO 全体を縮尺変換したりしない。パレット幅・余白を JavaScript の定数で引く方式と、`scrollWidth` を拡大寸法の算定元にする方式は廃止する。

### 2. 状態と復帰情報を分け、切り替えを一か所に集める

FIT が所有するモードは `normal` と `fit` の一つの値とする。CSS クラス、開始・解除操作、アクセシビリティ属性はそのモードから更新し、別の真偽値やボタンの表示状態を状態判定に使わない。旧 `appfit(0)`・`appfit(1)` と呼び出し元は同時に移行し、互換ラッパーを残さない。

NEO の DOM・painter・標準リサイズ API が使えない場合と Float 中は開始しない。復帰用情報は開始が可能と確認した後に一度だけ保存する。同じモードへの要求では保存情報を上書きせず、復帰情報を持つ間だけ有効な遷移を行う。

開始時はページのスクロール位置、フォーカス、変更する背景要素の `inert` とスクロール抑止用スタイルの従前値を保存する。FIT のレイアウトを適用し、正の枠寸法で標準リサイズが完了してから操作状態を確定する。開始を完了できなければ適用済みの指定を戻し、背景を操作不能のまま残さない。

利用者の通常の解除では FIT 用クラスを外し、変更した背景属性・スタイルだけを保存値へ戻す。通常レイアウトが確定してから `setZoom(1)` で倍率を 1 倍へ戻し、NEO をリサイズしてページ位置とフォーカスを復元する。保存先の要素がなくなった場合は通常表示の開始操作へ戻し、画面サイズ変更で不可能になったスクロール位置はブラウザーの有効範囲に収める。

### 3. 背後の操作だけを抑止し、NEO の入力を奪わない

専用表示中は背景のページスクロールを抑止し、作業領域の外側の DOM 分岐を `inert` にして背後へのキーボード移動・操作を防ぐ。作業領域を含む祖先全体を `inert` にしない。フォーカスは専用表示内へ移し、解除操作をキーボードでも利用可能にする。

ページ全体への無条件なキー抑止は行わず、Escape を FIT の解除キーとして横取りしない。描画領域・外部パレット内のスクロール、NEO のショートカット、入力欄、確認ダイアログを妨げない。

### 4. レイアウト確定後のサイズ通知だけを NEO へ渡す

描画アプリのホスト側配置枠を `ResizeObserver` で監視し、`requestAnimationFrame` で同一フレームの通知をまとめる。CSS が決めた実寸法が変わった場合だけ `Neo.resizeCanvas()` を呼ぶ。NEO の表示用バッファは監視対象にせず、自己誘発する通知の循環を避ける。

FIT の開始・解除では変更後の枠に対して通知を完了する。FIT 中の表示領域の変化にも同じ経路を使い、通常表示・Float 中やゼロ寸法に対する不要な更新を行わない。解除・Float への遷移では不要になった予約通知を取り消す。

`setZoom(1)` は利用者の通常の解除操作でのみ呼ぶ。開始・FIT 中のリサイズ・Float への切り替え・開始失敗の復旧では呼ばない。追加の `updateDestCanvas()` は呼ばず、標準リサイズによる再描画を使う。開始・FIT 中のリサイズでは現在の倍率を保持し、視点と表示範囲の制限は NEO に任せる。画像・レイヤー・履歴は再作成しない。

### 5. Float へは所有権を引き渡す

Float の開始は `neo:fullscreenchange` の通知で受け取り、FIT の背景操作抑止とレイアウトを解除する。この終了理由では倍率をリセットせず、ページのフォーカスを復元せず、NEO が既に行ったコンテナ移動・再描画を上書きしない。FIT 側から `Neo.fullScreen` を変更したり Float ボタンを疑似クリックしたりしない。

Float 終了後の FIT モードは `normal` のままとし、自動再開しない。Float の確認をキャンセルした場合は通知がないため、専用表示を維持する。Float 中の FIT 開始要求も無効とし、二つの表示モードを重ねない。

### 6. 新動作の実画面検証を完了条件にする

実装前に、現行版では専用表示・倍率保持・背景操作抑止が成立しないことを仕様のシナリオで確認する。現行 v1.8.8 に対して、過去の `Neo.resizeCanvas is not a function` を再現条件として要求しない。

実装後は両テーマで、表示領域・パレット・解除ボタンの画面と実寸法、通常解除と Float 遷移、初期化遅延、反復、狭い画面、ズーム・スクロール、両レイヤーの画素・表示状態・履歴と Undo/Redo を検証する。背景に戻るフォーカスやページ位置も操作で確認する。

既存のソース文字列に依存する FIT テストは削除し、別の文字列へ固定し直さない。この変更だけのために恒久的なブラウザー依存を増やさず、一時環境でシナリオ別の結果を記録する。既存 FIT・ローダー・Float の調査成功を、新設計の受け入れ完了へ流用しない。

## Risks / Trade-offs

- NEO の標準 API と Float 通知への依存 → 実装時の実資産を記録し、両テーマで検証する。API を持たない旧版向けの代替処理は追加しない。
- 背景の抑止を解除し忘れると通常ページが操作不能になる → 利用者の解除、開始失敗、Float 開始で同じ解除経路を使い、変更した属性・スタイルを正確に復元する。
- 固定配置の重なりや領域内スクロールで操作部品が隠れる → 通常・狭幅・低高さの画面と NEO の確認・メニューを実画面で確認する。小画面でのスクロールは許容する。
- 通知の循環・重複や Float 後の遅延通知で表示が壊れる → ホスト枠だけを監視し、実寸法とモードを確認し、不要な予約を取り消す。
- 専用表示と倍率の扱いは既存 FIT の操作感を変える → 開始・リサイズでは倍率保持、通常解除だけ 1 倍へ戻すことを仕様と更新履歴へ明示し、Float の標準動作を変えない。旧来のページ内拡大は互換動作として残さない。

## Migration Plan

実装時は両テーマの FIT スクリプト、描画テンプレート、操作部品、Sass と生成 CSS を一緒に更新し、旧呼び出し・固定値・不要な初期寸法データを削除する。既存の NEO ローダーと運用設定・DB・投稿画像は変更しない。

検証手順と結果、更新履歴を同時に更新する。問題時は両テーマの関連資産を一組で戻し、旧テンプレートと新しい制御処理を混在させない。本設計修正だけでは実装・受け入れ検証を完了扱いにしない。
