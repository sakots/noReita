# 開発

## ローカルでの文法テストなど

Linux/WSL上では、プロジェクトのルートディレクトリで以下を実行してください。

```bash
./scripts/lint-php.sh
./scripts/smoke-test.sh
./scripts/integration-test.sh
```

別名のPHPコマンドでテストする場合は、`PHP_BIN`を指定します。例えばPHP 8.1のコマンドが`php81`の場合は次のように実行できます。

```bash
PHP_BIN=php81 ./scripts/lint-php.sh
PHP_BIN=php81 ./scripts/smoke-test.sh
PHP_BIN=php81 ./scripts/integration-test.sh
```

`./scripts/lint-php.sh`ではPHP構文チェック、
`./scripts/smoke-test.sh`ではスモークテスト、
`./scripts/integration-test.sh`ではHTTP結合テストが行なえます。

HTTP結合テストは一時ディレクトリ内の設定を切り替えて検証します。テスト用PHP開発サーバーでは`opcache.enable=0`を指定し、変更前の設定がキャッシュから読み込まれないようにします。CLI用の`opcache.enable_cli=0`だけでは、開発サーバーのOPcacheは無効になりません。実運用のOPcache設定は変更しません。

成功すると最後に概ね以下のように表示されます。

```txt
Smoke tests: 154 passed, 0 failed.
Integration tests: 339 passed, 0 failed.
```

レンタルサーバーではなく、PHPと必要な拡張機能をインストールしたローカル開発環境またはCIで実行する想定です。

`board.page_size`（1ページの表示スレッド数）は1以上の整数に限定します。0は無制限の意味ではなく、負数と同様に設定エラーとして起動時に拒否します。回帰テストでは0・負数の拒否と、1・既定値10の受理を確認します。

`board.max_threads`（保存スレッド数の上限）も1以上の整数に限定します。0・負数は起動時の設定検証で拒否し、閲覧に伴う自動削除処理へ進ませません。既定値1000と通常の自動削除の動作は変更しません。回帰テストで0・負数の拒否と1・既定値の受理を確認し、HTTP結合テストでは0を設定して一覧へ複数回アクセスしても既存投稿が変わらないことを検証します。

通常一覧の`page`はカタログと同様に正の整数として検証します。省略・0・負数・小数・指数表記・配列・整数範囲を超える値は1ページ目を使い、有効な整数が最終ページを超える場合は最終ページへ収めてからオフセットを計算します。空の掲示板も1ページとして扱います。両テーマのHTTP結合テストで、不正入力と最大整数を含むページ範囲の補正を確認します。

直接アップロードしたGIF・パレットPNGは、縮小しない場合もWebPへ変換できるよう、エンコード前にフルカラー化します。回帰テストでは、縮小上限より小さい画像の変換後の寸法と透明部分を確認します。

画像の入力上限（`limits.image_width`・`limits.image_height`）と保存時の縮小寸法は独立して設定できます。縮小寸法が入力上限より大きくても起動を許可し、画像の拡大は行いません。入力上限を超える画像は従来どおり拒否します。

直接アップロードするJPEGは、EXIFのOrientation（1～8）の回転・反転を反映してから縮小します。保存後の寸法には補正後の値を使い、EXIFなどのメタデータは従来どおり除去します。EXIF拡張は必須にせず、JPEGのAPP1内の向き情報だけを読み取ります。向き情報がない場合や不正な場合は無補正で処理します。回帰テストでは全8方向、両バイト順、縮小後の寸法と画素の配置を確認します。

画像差し替えは投稿用CSRF設定にかかわらずPOST・同一オリジン・CSRFトークンを検証します。投稿の認可は描画開始時の差し替えコードと所有者に結び付け、一時画像の所有者も照合します。NEO・ChickenPaint系の保存後のGETは確認フォームの表示だけに使い、ボタンを押したPOSTで差し替えます。結合テストでは不正要求で投稿・関連ファイルが変わらないことと、両テーマの各描画ツールの送信経路を確認します。

画像差し替えの公開状態は保存処理での取得時だけでなく、更新SQLでも投稿自身と親スレッドを確認します。取得後に投稿・親が非表示になった場合や親が削除された場合は更新を拒否し、既存のロールバック処理で差し替え用に作成したファイルを削除します。回帰テストでは取得と更新の間に公開状態を変え、DBが変更されないことと公開中の投稿・返信は正常に更新できることを確認します。

続き描きは確認画面のGETだけでなく描画開始のPOSTでも、公開投稿と画像・動画ファイルの対応を検証します。管理者や投稿パスワードを知る利用者でも非表示投稿は公開経路から描画できません。結合テストでは画像・動画・PSD・CHIからの正常な開始、非表示化後の直接POST、投稿番号やファイル名の偽装を検証します。

続き描きで認証が必要な場合、パスワード未入力は400で入力を案内し、不一致は403でパスワードが間違っていることを案内します。記事が存在しない場合は404とし、認証失敗のメッセージには混ぜません。両テーマでKlecksから別ツールへ切り替える場合の認証エラーと、正しいパスワードでの描画開始を確認します。

公開APIの返信は、返信自身と親スレッドの両方が公開されている場合だけ返します。親が存在しない返信も除外します。検索・カタログの件数にも同じ条件を適用し、HTML表示と揃えます。親の非表示・再公開では返信自身の公開設定を変更せず、個別に非表示にした返信は親を再公開しても非表示のままです。

返信保存時にもトランザクション内で親投稿の公開状態を確認し、非表示・削除済みの親や返信番号への投稿は404で拒否します。管理者も通常の投稿経路では非表示の親へ返信できません。拒否時は親の並び順・投稿件数・既存画像を変更せず、描画の一時ファイルを維持し、通常アップロードで作ったファイルは削除します。

「そうだね」は公開状態の条件を加算SQLにも適用し、投稿自身や親スレッドが非表示の場合、親が存在しない返信、存在しない番号は加算せず404で拒否します。通常POSTとAjaxで同じ判定を使い、既存の同一オリジン・CSRF検証を維持します。加算と返却件数の取得は同じトランザクションで行います。

新規投稿・返信の「そうだね」は保存時に0へ固定し、フォームの送信値は初期値に使いません。回帰テストでは正数・負数・省略した値を確認し、既存投稿の加算と編集時の件数保持も検証します。

投稿処理モジュールの互換性要件は20261010です。部分更新で古い`post.inc.php`が残っている場合は投稿前に更新を求めるメッセージで停止します。DBスキーマは変更しません。

公開APIの検索語が100文字を超える場合は、検索条件の検証エラーだけを400の入力エラーへ変換します。DB処理などの内部障害は500のままです。回帰テストでは `q` と `search` の100文字・101文字の境界を、ASCIIと日本語で確認します。

OGPの画像説明は空文字列の場合だけ件名に戻し、「0」も説明として保持します。両テーマのHTTP結合テストで、通常画像・NSFWのぼかし済みサムネイル・画像なしの出力と、説明のHTMLエスケープを確認します。

記事表示と続き描きでも同じ公開条件を使い、親が非表示または存在しない返信は404で拒否します。Misskey確認画面ではその返信を非表示投稿と同様に扱い、本文や画像の表示には既存の投稿者・管理者認証を必要とします。管理者用の取得処理や返信自身の公開設定は変更しません。

DB処理モジュールの互換性要件は20261009です。部分更新で旧モジュールが残っている場合は、メソッド呼び出し前に更新を求めるメッセージで停止します。DBスキーマの変更や設置者による移行操作は不要です。

画像差し替えは保存直前にも公開投稿を再取得します。描画中に投稿自身や親スレッドが非表示になった場合は404で拒否し、既存の画像・関連ファイルと一時画像を変更しません。結合テストでは、認可取得後の非表示化と、拒否後の正常な差し替えを検証します。

差し替え認可には描画開始時の画像名も保持し、認可発行時には入力画像との一致を確認します。保存時に現在の画像名と一致しなければ409で拒否し、新しい投稿画像・関連ファイルと古い描画の一時ファイルを維持します。DB更新の競合条件にも開始時の画像名を使います。結合テストでは別々のセッションから同じ画像の描画を開始し、先に保存した画像を後から古い描画で上書きできないことを検証します。

コメント編集では、認可時に取得した画像名・NSFW設定・サムネイル名を更新SQLでも照合します。画像差し替えや別のNSFW変更が先に保存された場合は409で拒否し、新しい画像・設定・本文を上書きしません。NSFW変更のために生成したサムネイルは、競合による失敗時も既存のロールバック処理で片付けます。「そうだね」の加算は照合対象にせず、通常の編集を妨げません。

編集フォームには、投稿番号・画像名・NSFW設定・サムネイル名から計算した画像状態のハッシュを隠し項目として渡します。保存時は投稿者・管理者の認可後に現在の状態と照合し、古い状態・項目の欠落・不正値は409で拒否します。この値は認証やCSRFの代わりではなく、フォーム表示後の変更を検出するためのものです。本文編集や「そうだね」の加算だけでは値を変えません。更新SQLの照合も残し、フォーム送信後の競合も引き続き拒否します。両テーマで古いフォーム・欠落・不正値の拒否と、開き直したフォームによる編集を確認します。

この修正の適用時は、本体と使用するテーマの編集テンプレートをまとめて更新してください。旧テンプレートは画像状態の項目を送らないため、編集の保存が409で拒否されます。

## サムネイルの寸法制限

外部画像のサムネイル追加処理は、HTMLエスケープ済みの本文を受け取ります。抽出したURLのHTMLエンティティを一度だけ復号し、取得・キャッシュには元のURLを使います。リンクを生成するときに改めてHTMLエスケープし、本文の置換には抽出時の表記を使います。置換は元の本文に対してURL全体の完全一致で一度だけ行い、長いURLの一部や生成したHTMLを再置換しません。クエリの`&`、パーセントエンコード、エンティティに似た文字列を含むURLと、属性値のエスケープを回帰テストで確認します。同じ先頭を持つURLは記載順を変えて確認し、件数制限やキャッシュ未取得で置換対象にならないURLも変更しないことを検証します。

投稿画像・外部画像のサムネイルは、元画像を拡大せず、縦横比を保って指定サイズの正方形内に縮小します。指定サイズが大きい場合も一辺2048pxまでとし、出力は最大4,194,304画素に制限します。端数は切り捨て、幅・高さは最低1pxにします。NSFWのぼかし処理、代替画像、アニメーションAVIFの中間キャンバスにも同じ寸法計算を使い、縦長画像から過大な出力領域を確保しないようにします。元画像のデコードに必要なメモリは、この出力制限とは別です。

画像処理・サムネイル処理モジュールの互換性要件は20261008です。部分更新で旧モジュールが残っている場合は、共通の寸法計算を呼び出す前に更新を求めるメッセージで停止します。

## 不要コードの整理

未使用コードを削除する前に、アプリケーション本体、テスト、開発ツール、資料を検索し、呼び出し元がないことを確認します。外部向けの設定、URL、テーマの拡張点、データ移行処理は、参照が見つからないだけでは削除しません。テーマの分岐を削除する場合は、eda と monoreita の呼び出し元と部品を同時に確認します。削除後は既存の構文チェックと回帰テストを実行し、関連する資料の記述も残さないようにします。

## Sassのコンパイル

配布テーマのスタイルはSassで管理しています。`noreita/theme/eda/css/` と
`noreita/theme/monoreita/css/` 以下の `.scss` を変更した場合は、生成されるCSSも更新してください。

初回のみ、プロジェクトルートでNode.jsの開発依存をインストールします。

```bash
npm ci
```

一度だけ全Sassをコンパイルする場合は、次を実行します。

```bash
npm run sass:build
```

開発中に監視して自動コンパイルする場合は、次を実行したままにします。

```bash
npm run sass
```

ビルドスクリプトは、リポジトリ配下にある先頭が`_`ではないすべての`.scss`を対象にします。各入力ファイルと同じディレクトリへ、以下を出力します。

- 展開済みCSS: `ファイル名.css`
- 圧縮版CSS: `ファイル名.min.css`
- それぞれのsource map: `.css.map` と `.min.css.map`

`_color.scss`や`_eda_conf.scss`のように先頭が`_`のファイルはpartialです。単体のCSSは生成されませんが、それらを`@use`するエントリーポイントを再コンパイルしてください。生成済みの`.css`、`.min.css`、source mapは直接編集せず、Sassを修正してからビルド結果をコミットします。

テーマを変更した後は、Sassビルドに加えて両テーマの診断と差分確認を実行してください。

```bash
php plugins/check-theme.php --root=noreita --theme=eda
php plugins/check-theme.php --root=noreita --theme=monoreita
git diff --check
```
