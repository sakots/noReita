# バックアップ・復元手順

## 障害や誤削除に

最低限、次を一緒に保存します。

- `config.php`
- `reita.db`などのSQLiteデータベースファイル
- `img/`、`thumb/`、`thumbnail/`、`webp/`、`avif/`の各ディレクトリ
- 必要なら描画アニメーション・PSDなどの保存先

SQLiteは稼働中にDBファイルだけコピーすると、WAL使用時に最新データが含まれない可能性があります。そのため、管理モード停止中にコピーするか、SQLiteのバックアップ機能を使う手順が必要です。

## DBマイグレーション時の自動バックアップ

v3.5以降では、DBスキーマの更新前に`backup/`ディレクトリへ整合性の取れたSQLiteバックアップを自動作成します。ファイル名には更新前のスキーマバージョンと日時が入ります。

自動バックアップはDBだけが対象です。`config.php`や投稿画像は含まれないため、通常のバックアップの代わりにはなりません。復元する場合は稼働を止め、現在のDBを別の場所へ退避してから、バックアップファイルを`config.php`で指定したDB名へ戻してください。

## 投稿削除時の一時退避

画像付き投稿を削除するときは、関連画像・動画・サムネイルと復元用マニフェストを`backup/delete-staging/`へ一時退避してからDBを更新します。DB削除に失敗した場合は自動的に元の場所へ復元し、成功した場合は一時退避ファイルを削除します。

PHPプロセスの強制終了やサーバーダウンで処理が中断した場合は、次回起動時に自動復旧します。マニフェストに記録された記事がDBに残っていれば関連ファイルを`img/`へ戻し、記事が削除済みなら退避ファイルの削除を完了します。別リクエストが削除処理中の場合は、ロックを確認して復旧対象から除外します。

通常、このディレクトリにファイルは残りません。障害後に`delete-*`ディレクトリが残っている場合は、すぐに削除せず、DBと`img/`の状態を確認してください。`backup/`全体へのHTTPアクセス拒否設定も維持してください。
